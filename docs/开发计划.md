# intranet-play 五子棋 · 详细开发计划

> 目标：用 Go 做一款**内网联机、命令行双人对战五子棋**（Host 权威、TCP + JSON、15×15、无禁手）。

---

## 0. 范围与约定

| 项 | 决定 |
|---|---|
| 语言 / 模块 | Go 1.21+，模块名建议 `intranet-play` |
| 路径 | `DEMO/golang/intranet-play` |
| 棋盘 | 15×15，无禁手；满盘和棋 |
| 人数 | 严格 2 人；Host=黑先手，Join=白 |
| 协议 | TCP，一行一条 JSON（`\n` 分隔） |
| UI | 第一版纯 `fmt` + stdin；不做 TUI 框架 |
| 非目标（MVP 不做） | 观战、AI、排行榜、公网穿透、UDP 自动发现、禁手规则 |

**验收标准**：两台同网段机器（或本机两个终端）能开房、落子、判胜、断线提示。

### 默认产品形态

```text
intranet-play host --port 9527 --name Alice   # 先手下黑
intranet-play join --addr 192.168.x.x:9527 --name Bob
```

### 推荐目录结构

```text
intranet-play/
├── cmd/intranet-play/main.go
├── internal/
│   ├── protocol/     # 消息定义
│   ├── netx/         # TCP 读写（避免与标准库 net 重名）
│   ├── room/         # 两人房间、角色分配
│   ├── game/         # 棋盘、落子、判胜
│   └── ui/           # 打印棋盘、读坐标
├── docs/
│   └── 开发计划.md
├── go.mod
└── README.md
```

## 阶段 2：单机棋盘引擎（约 1 天）

### 任务（`internal/game`）

1. 数据结构：`Size`、`Cells [][]int`、`Turn`、`Winner`、`MoveCount`
2. `NewBoard(size int)`
3. `Place(x, y int) error`
   - 校验：范围内、空位、未终局、颜色=当前回合
   - 落子后切回合；若胜则设 `Winner` 且不再切回合
4. `checkWin(x, y)`：横 / 竖 / 两对角，连续 ≥5
5. `IsDraw()`：无胜且格子满
6. `Clone()` 或导出只读快照，供序列化
7. 单元测试：
   - 合法落子、占位拒绝、越界拒绝
   - 横/竖/斜五连各 1 例
   - 未满五不胜、满盘和棋

### 交付

- `go test ./internal/game` 全绿；可写一个本机双人轮流的小 demo（可选）

### 完成定义

- 不依赖网络也能完整打完一局并判胜负

### 核心接口草图

```go
type Board struct {
    Size      int
    Cells     [][]int // 0 空 / 1 黑 / 2 白
    Turn      int     // 1 or 2
    Winner    int
    MoveCount int
}

func NewBoard(size int) *Board
func (b *Board) Place(x, y int) error
func (b *Board) CheckWin(x, y, color int) bool
func (b *Board) IsDraw() bool
```

## 阶段 3：协议与编解码（约 0.5 天）

### 任务（`internal/protocol`）

1. 定义消息类型常量：`join` `welcome` `place` `state` `chat` `error` `resign` `restart` `leave`
2. `Envelope{Type, From, Payload}`
3. 各 Payload 结构体：
   - `JoinPayload{Name}`
   - `WelcomePayload{Color, Opponent, Size}`  // color: black/white
   - `PlacePayload{X, Y}`
   - `StatePayload{Board, Size, Turn, Last, Winner, Draw, You}`
   - `ChatPayload{Text}`
   - `ErrorPayload{Message}`
4. `Encode(msg) []byte`（末尾加 `\n`）
5. `DecodeLine(line) (*Envelope, error)`
6. 表驱动测试：往返序列化不错位

### 协议示例

```go
type MsgType string

const (
    TypeJoin    MsgType = "join"
    TypeWelcome MsgType = "welcome"
    TypePlace   MsgType = "place"
    TypeState   MsgType = "state"
    TypeChat    MsgType = "chat"
    TypeError   MsgType = "error"
    TypeResign  MsgType = "resign"
    TypeRestart MsgType = "restart"
    TypeLeave   MsgType = "leave"
)

type Envelope struct {
    Type    MsgType         `json:"type"`
    From    string          `json:"from,omitempty"`
    Payload json.RawMessage `json:"payload,omitempty"`
}
```

`state` 载荷示例：

```json
{
  "board": [[0,0,1]],
  "size": 15,
  "turn": "black",
  "last": {"x": 7, "y": 7},
  "winner": "",
  "draw": false,
  "you": "white"
}
```

### 交付

- 协议包独立可测，不依赖 TCP

## 阶段 4：TCP 读写层（约 0.5～1 天）

### 任务（`internal/netx`）

1. `Conn` 封装：`Send(Envelope)`、`Receive() <-chan Envelope` 或回调
2. 读循环：`bufio.Scanner`，限制单行最大长度（防恶意大包，如 1MB）
3. 写侧加 mutex，避免并发写交叉
4. 连接关闭时关闭 channel / 通知上层
5. Host：`Listen(addr)` → `Accept` 一次（或第二次立即拒绝并关闭）
6. Client：`Dial(addr)` + 超时（如 5s）

### 交付

- 两个进程能互发任意 `chat` 并打印

### 注意

- Windows 下注意程序退出时关闭 listener
- 错误要向上返回，不要只在库里 `log.Fatal`

## 阶段 5：房间与对局编排（约 1～1.5 天）

### 游戏状态机

```text
WaitingOpponent → Ready → Playing → Finished
                      ↑         │
                      └─ 再来一局 ┘
```

| 阶段 | 行为 |
|---|---|
| WaitingOpponent | Host 等第二人连接 |
| Playing | 轮到谁，谁发 `place`；对方只收 `state` |
| Finished | 广播胜者；可选 `restart` |

### 任务（`internal/room`）

1. **HostRoom**
   - 等对手 `join` → 校验名字非空 → 回 `welcome`（对方 white）→ 本地也定为 black
   - 广播初始 `state`
   - 统一入口处理消息：`place` / `chat` / `resign` / `restart` / `leave`
   - `place`：校验「是否该对手下」→ `board.Place` → 广播新 `state`
   - Host 自己的落子：同样走 `board.Place` 再广播（不要两套逻辑）
   - 第三人连接：发 `error` 后断开
2. **ClientRoom**
   - 连上发 `join`
   - 收 `welcome`/`state`/`error`/`chat` 更新本地视图
   - 仅在 `Turn == You` 且未终局时允许发 `place`
3. 断线：对端断开 → 打印「对手已离开」→ MVP 直接结束进程即可
4. 认输：`resign` → Host 设对方获胜 → 广播 `state`
5. 再来一局：终局后任一方发 `restart`，由 Host 重置棋盘并广播

### 建议并发模型

```text
Host:
  goroutine: 读对手 TCP → inbox
  goroutine: 读本地 stdin → inbox
  主循环: 单线程消费 inbox，改 board，发 state   // 无锁改棋盘
```

Client 同理：网络进、stdin 进、单线程处理。

### 交付

- 本机两个终端完整对下一局并分出胜负

## 阶段 6：终端 UI（约 0.5～1 天）

### 任务（`internal/ui`）

1. `Render(state)`：坐标轴 + `·●○`，高亮最后一手（如用 `◆`/`◇`）
2. 状态行：双方名字、颜色、轮到谁、胜负/和棋
3. 输入解析：
   - `7,7` / `7 7` → place
   - `chat xxx` → chat
   - `resign` / `restart` / `quit`
4. 非法输入本地提示，不发网
5. Windows：文档注明 UTF-8；必要时 README 写 `chcp 65001`
6. 每步清屏可选（`cls` / ANSI）；MVP 可只追加打印，避免清屏坑

## 实现时注意的技术点

1. **权威只在 Host**：Client 展示用本地缓存，冲突以 Host `state` 为准
2. **单线程推进棋盘**：避免 `Place` 竞态
3. **协议向后兼容**：未知 `type` 忽略并打日志，方便以后加字段
4. **坐标约定写死**：`x` 列、`y` 行，原点左上，文档与 UI 一致
5. **不把 `net.Conn` 暴露给 UI**：房间层转换，方便以后换 WebSocket
