# intranet-play 21 点 · 开发计划

> 目标：在现有 `intranet-play` 上新增**内网联机、终端 2~6 人 21 点（Blackjack）**
> （Host 权威、TCP + JSON-line、最小改造、不动五子棋与斗地主）。

---

## 0. 范围与约定

| 项 | 决定 |
|---|---|
| 人数 | 2~6 人（房主也参与，所有人都是闲家） |
| 庄家 | **虚拟庄家**：由服务端按固定规则自动打，不占座位、不参与下注 |
| 牌 | 52 张（`ddz.NewDeck()` 去掉大小王），单副牌，**每局重新洗牌**（不做牌靴与算牌） |
| 计分 | 筹码制，初始 100（`-chips` 可配），输光自动补满并记日志 |
| 命令入口 | `intranet-play bj host` / `intranet-play bj join` |
| UI | bubbletea TUI，延续 `nx-sync` 数据面板风格 |
| 改造路线 | 最小改造：协议纯增量，房间层把斗地主的"3 人广播"泛化成 N 人 |
| 非目标（本版不做） | 保险、分牌（split）、投降、多副牌牌靴、算牌提示、观战、AI 托管、超时自动停牌 |

**验收标准**：2~6 人开房，各自下注、要牌/停牌/双倍、庄家自动补牌、逐人结算与筹码变化正确，
庄家的暗牌在结算前对所有人保密。

### 默认产品形态

```text
intranet-play bj host --port 9988 --name Alice --chips 100
intranet-play bj join --addr 192.168.x.x:9988 --name Bob
```

### 已确认的默认项

- **虚拟庄家**：庄家没有决策自由（<17 必须要牌、≥17 停），所以不需要人当庄；这样 2 个人也能玩，房主不旁观
- 手牌**全部公开**（和真赌桌一样，其他闲家的牌是明牌），只有**庄家的暗牌**在结算前保密
- 点数：2-10 按面值，J/Q/K 记 10，A 先按 11 算、爆牌时逐个降为 1
- **黑杰克**（起手两张即 21 点）赔 3:2；注额为奇数时向下取整
- **双倍**：仅限起手两张时，加注一份、只补一张牌、然后自动停牌
- 庄家 S17（软 17 也停）；平局退还注额
- 全员下注完毕后**自动发牌**，不需要额外命令
- 一轮结束后任一玩家 `next` 进入下一轮下注

### 本作的关键差异：**不需要单播**

斗地主必须给每个人单独下发手牌；21 点里闲家的牌本来就是明牌，唯一要藏的是**庄家的暗牌**——
而它只要"不下发"就够了，不需要发给任何人。所以公共视图里用一个占位符表示暗牌即可，
`internal/room` 的 `unicast` 在这款游戏里用不上。

## 2. 规则规格

### 2.1 点数

```text
2-10  → 面值
J/Q/K → 10
A     → 11，若总点数超过 21 则把一张 A 降为 1（多张 A 依次降）
```

- `Score(cards)` 返回 `(点数, 是否软牌)`；软牌指"还有一张 A 按 11 算"
- `IsBlackjack(cards)`：恰好两张且点数 21
- `IsBust(cards)`：点数 > 21

### 2.2 行动

| 命令 | 条件 | 效果 |
|---|---|---|
| `bet N` | 下注阶段 | 押 N 注；所有座位下注完成后自动发牌 |
| `hit` | 轮到自己 | 要一张；爆牌即出局 |
| `stand` | 轮到自己 | 停牌 |
| `double` | 轮到自己且**只有起手两张** | 加注一份、只补一张、自动停牌（爆牌算出局） |

- 闲家行动按座位顺序，前一个人停牌/爆牌后轮到下一个
- 全员结束 → 庄家按规则补牌 → 结算 → 展示结果

### 2.3 庄家

```text
点数 < 17 必须要牌；>= 17 停（软 17 也停）
庄家爆牌 → 所有未爆的闲家赢
```

### 2.4 结算

| 情况 | 结果 |
|---|---|
| 闲家爆牌 | 输掉注额 |
| 闲家黑杰克 vs 庄家非黑杰克 | 赢 1.5 倍（注额的 3:2，向下取整） |
| 闲家黑杰克 vs 庄家黑杰克 | 平局，退还注额 |
| 闲家点数 > 庄家点数（庄家未爆） | 赢 1 倍 |
| 闲家点数 == 庄家点数 | 平局，退还注额 |
| 庄家爆牌（闲家未爆） | 赢 1 倍；若闲家是黑杰克则仍按 1.5 倍 |

## 3. 状态机

```text
LOBBY → BETTING → PLAYING →(庄家自动补牌) → SETTLE → (next) BETTING
                                  ↑                      │
                                  └──── 筹码输光自动补满 ──┘
```

庄家补牌不需要玩家参与（规则固定），所以它**不占一个交互阶段**，
是 PLAYING 最后一名闲家行动结束后的一次自动步骤。

| 阶段 | 谁可以行动 | 广播内容 |
|---|---|---|
| LOBBY | 房主 `start`（人齐后） | 座位表、筹码 |
| BETTING | 每个未下注的座位 `bet N` | 各家注额（还没有牌） |
| PLAYING | 当前行动座位 `hit`/`stand`/`double` | 所有闲家手牌（明）、庄家明牌 + 暗牌占位 |
| SETTLE | 任意玩家 `next` | 庄家全手牌 + 每人输赢与最新筹码 |

## 4. 协议扩展

沿用 [`Envelope`](<../internal/protocol/message.go#L22-L26>)，**新增**消息类型（纯增量文件，
五子棋与斗地主消息一行不动）：

| 类型 | 方向 | payload |
|---|---|---|
| `BJ_LOBBY` | Host → 单人 | `{You, Seats[], Chips, Started}` |
| `BJ_START` | Host → 全员 | `{Round}` |
| `BJ_PUBLIC` | Host → 全员 | 见下（**庄家暗牌只有张数占位，没有牌面**） |
| `BJ_ACTION` | Client → Host | `{Kind: "bet"\|"hit"\|"stand"\|"double", Amount}` |
| `BJ_EVENT` | Host → 全员 | `{Seat, Text}` |
| `BJ_SETTLE` | Host → 全员 | `{Dealer []Card, Results [{Seat, Delta, Chips, Reason}]}` |
| `BJ_NEXT` | Client → Host | 请求下一轮 |

公共视图 `BJ_PUBLIC`：

```json
{
  "round": 3,
  "phase": "PLAYING",
  "turn": 1,
  "dealer": {"up": [{"id":0,"rank":14,"suit":0}], "hidden": 1, "score": 11, "soft": true},
  "seats": [
    {"seat": 0, "bet": 10, "status": "STOOD", "cards": [...], "score": 18, "soft": false, "chips": 110}
  ],
  "lastEvent": "Bob 要了一张，15 点"
}
```

**隐私红线**：`dealer.hidden` 只是张数，结算前**没有**任何字段携带暗牌牌面；
这条要有测试断言（和斗地主的"公共视图不含手牌"同款）。

## 5. 核心接口草图

```go
// internal/bj/card.go
type Card = ddz.Card   // 复用点数/花色/显示
type Rank = ddz.Rank

func NewShoe(rng *rand.Rand) []Card        // 52 张，已洗
func Score(cards []Card) (int, bool)       // (点数, 是否软牌)
func IsBlackjack(cards []Card) bool
func IsBust(cards []Card) bool

// internal/bj/game.go
type Game struct {
    Hands  []Hand      // 每个座位
    Dealer []Card
    Phase  Phase
    Turn   int
    Chips  []int
    Round  int
    // ...
}

func NewGame(rng *rand.Rand, seats, chips int) *Game
func (g *Game) Apply(seat int, act Action) ([]Event, error)  // 唯一入口
func (g *Game) PublicView() PublicView                        // 暗牌只给张数
func (g *Game) Settle() []Result                              // 结算明细
func (g *Game) NextRound()                                    // 进入下一轮下注
```

**关键约定**：与斗地主一致——客户端只发命令、只渲染视图；所有校验都在 `Apply` 里做，
失败返回 error → 单播 `ERROR`。

## 6. 并发模型

沿用斗地主那条已跑通的路径，只是座位数从 3 变成可配的 N：

```text
accept goroutine ──▶ conn[i] ──▶ forwarder goroutine ──┐
                                                        ├──▶ hubInbox chan Inbound{Seat, Envelope}
主循环（单线程）: select { hubInbox / 本地命令 / conn.Done / app.Done }
   └─ 改 Game 状态 → broadcast(BJ_PUBLIC) / 必要时 BJ_SETTLE
```

- 座位上限 6，超过的连接收到 `ERROR: room full` 后断开
- 有人掉线：本局作废回大厅（与斗地主同样处理，不做托管）

## 9. 验收清单

- [ ] 2~6 人开房；第 7 个连接被拒
- [ ] 各座位下注后自动发牌；某座位未下注时不会发牌
- [ ] 闲家两张明牌、庄家一明一暗；结算前公共报文里**查不到暗牌牌面**
- [ ] 非轮次玩家 `hit` 被拒；重复下注被拒；注额超过筹码被拒
- [ ] `double` 仅在起手两张时可用，用后只补一张并自动停牌
- [ ] 爆牌立即出局且不再发牌；庄家 <17 自动补牌、≥17 停
- [ ] 黑杰克赔 3:2、平局退还、庄家爆牌闲家通吃（含黑杰克仍按 3:2）
- [ ] 筹码变化正确；输光自动补满并记日志
- [ ] `next` 进下一轮；掉线本局作废回大厅
- [ ] 回归：`go test ./...` 全绿，五子棋与斗地主照旧可用

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| 暗牌从公共视图泄漏 | 视图里只有 `hidden` 张数；加断言测试；结算时才下发庄家全手牌 |
| 点数计算边界（多张 A、软 17） | 表驱动测试穷举 A 的组合 |
| 双倍后筹码不足 | `double` 校验筹码是否够加注一份，不够则拒绝 |
| 结算金额出现小数（3:2） | 整数筹码 + 向下取整，规则里写死并在 UI 注明 |
| 有人一直不下注卡住全员 | 房主可 `skip <seat>` 把该座位按最小注处理（P2，先记录） |
| 与既有游戏共用 protocol/netx 造成回归 | 只做增量；回归跑全量测试 |

## 12. 实现时注意的技术点

1. **牌模型复用**：`internal/bj` 用类型别名指向 `internal/ddz` 的牌（`type Card = ddz.Card`），
   显示与记法零重复；等第三款牌类游戏出现时再考虑抽 `internal/cards`
2. **权威在房主**：客户端不判点数、不判输赢，只渲染
3. **随机数在房主**：洗牌可注入种子，便于复现
4. **协议向后兼容**：未知 `type` 忽略
5. **与斗地主的房间代码不共用**：先照抄再抽象，避免现在就去动已经提了 PR 的 ddz 代码
