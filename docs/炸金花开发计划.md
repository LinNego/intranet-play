# intranet-play 炸金花 · 开发计划

> 目标：在现有 `intranet-play` 上新增**内网联机、终端 2~6 人炸金花（三张牌）**
> （Host 权威、TCP + JSON-line、最小改造、不动五子棋/斗地主/21 点）。

---

## 0. 范围与约定

| 项 | 决定 |
|---|---|
| 人数 | 2~6 人（房主也参与） |
| 牌 | 52 张（`ddz.NewDeck()` 去掉大小王），每人 3 张，每局重新洗牌 |
| 筹码 | 初始 100（`-chips`），底注 ante 默认 1（`-ante`） |
| 注额上限 | `-maxstake` 默认 20：到顶之后不能再加注 |
| 轮数上限 | `-maxrounds` 默认 6：一圈算一轮，到顶之后只能比牌或弃牌（防止无限跟注） |
| 命令入口 | `intranet-play zjh host` / `intranet-play zjh join` |
| UI | bubbletea TUI，延续 `nx-sync` 数据面板风格 |
| 非目标（本版不做） | 235 吃豹子等地方规则、买牌/换牌、抽水、观战、AI 托管、超时自动弃牌 |

**验收标准**：2~6 人开房，各自底注入池、闷牌/看牌、跟注/加注/弃牌、比牌分出胜负、
奖池结算与筹码变化正确；**没看牌之前服务端不会把你的牌发给你**。

### 默认产品形态

```text
intranet-play zjh host --port 9988 --name Alice --chips 100 --ante 1
intranet-play zjh join --addr 192.168.x.x:9988 --name Bob
```

### 已确认的默认项

- **看牌才知道自己的牌**：开局每人 3 张，但服务端**不下发**，直到你 `look`。
  这是炸金花的核心（闷牌），也是本作唯一比斗地主更严格的隐私要求
- **闷牌半价**：闷牌跟注只付明牌的一半（`max(1, 注额/2)`，整数除）
- **闷牌平局占优**：比牌时若大小完全一样，恰好一方闷牌则闷牌方赢；都明或都闷则**主动比牌的人输**
- **比牌花费**：付一份跟注（闷牌按半价），输的人弃牌；**牌面只单播给比牌的双方**，其他人只看到结果
- 只剩一人没弃牌 → 他拿走奖池，本局结束
- 筹码输光即出局（与 21 点一致），只剩一人有钱整桌结束，房主可 `restart`
- 不看牌也能一直跟（跟注不改变注额），所以用**轮数上限**逼出结局：到顶只能比牌或弃牌

### 本作的两个关键点

1. **手牌必须按下发时机单播**：斗地主是"发牌即下发"，炸金花要**看牌之后才下发**。
   所以 `PrivateView` 里的 `Cards` 在 `Looked == false` 时为空数组，而不是"发下去但界面不显示"——
   后者等于把牌送到了客户端，随便改个客户端就看到了
2. **比牌是一对一的**：结果对全场公开（谁出局），但**牌面只发给比牌的两人**，
   所以单播要能指定座位，而不是只有"发给自己"

## 2. 规则规格

### 2.1 牌型与大小

从大到小：

| 牌型 | 说明 | 比较方式 |
|---|---|---|
| **豹子** `BAOZI` | 三张同点 | AAA 最大，222 最小 |
| **同花顺** `TONGHUASHUN` | 同花色且连续 | 比最大张；A23 是最小的顺子 |
| **金花** `JINHUA` | 同花色 | 依次比三张（从大到小） |
| **顺子** `SHUNZI` | 连续三张 | 比最大张；A23 最小 |
| **对子** `DUIZI` | 一对 + 一张 | 先比对子点数，再比单张 |
| **散牌** `SANPAI` | 其它 | 依次比三张（从大到小） |

- **花色不参与比较**：完全一样大时返回"平局"，由比牌规则裁决（见 2.3）
- 顺子判定：三张点数连续。`A23` 视为顺子且最小（按"3 最大"处理），`QKA` 最大
- 代码里把比较结果压成 `Hand{Kind, Key []Rank}`：先比 `Kind`，再按 `Key` 逐个比

### 2.2 下注

```text
开局：所有在局玩家各付底注 ante 进奖池 pot，注额 stake = ante
轮转：按座位顺序，每人一次
```

| 命令 | 效果 |
|---|---|
| `look` / `看牌` | 变成明牌（免费，只影响自己，随时可用） |
| `call` / `跟` | 跟注：付 `cost`，注额不变 |
| `raise N` / `加 N` | 加注到 N（`stake < N <= maxstake`），付新的 `cost` |
| `fold` / `弃` | 弃牌出局（本局已投入的不退） |
| `compare <座位>` / `比 N` | 跟指定在局玩家比牌：付一份 `cost`，输的人弃牌 |

其中 **`cost`（本回合要付多少）**：

```text
明牌：cost = stake
闷牌：cost = max(1, stake / 2)      // 整数除，向下取整
```

- 筹码不够付 `cost` 的人**只能弃牌**（不能欠账，与 21 点的"输光出局"一致）
- `stake == maxstake` 之后不能加注；`已进行的轮数 >= maxrounds` 之后只能 **比牌或弃牌**
- 一圈 = 所有在局玩家各行动一次；每圈结束 `轮数 + 1`

### 2.3 比牌

```text
比牌者付 cost → 双方亮牌比较
  大小不同       → 小的一方弃牌
  完全一样大     → 恰好一方闷牌：闷牌方赢
                   都明或都闷  ：主动比牌的一方输（"比牌者输"）
```

- 被比的人**不需要付钱**（钱由发起方出）
- 结果对全场公开（谁出局），**牌面只单播给比牌的两人**
- 只剩一人没弃牌 → 他拿走奖池

### 2.4 结算

| 情况 | 结果 |
|---|---|
| 只剩一人没弃牌 | 赢家拿走全部奖池，其余人本局投入不退 |
| 赢家筹码变化 | `+pot - 自己本局投入`（净额） |
| 筹码为 0 | 出局（与 21 点一致），不再参与，直到房主 `restart` |
| 只剩一人有筹码 | 整桌结束，他赢到最后 |

## 3. 状态机

```text
LOBBY → BETTING →(只剩一人 / 比牌到只剩一人)→ SETTLE → (next) BETTING
                                                        │
                                          只剩一人有钱 → OVER（房主 restart）
```

| 阶段 | 谁可以行动 | 广播内容 |
|---|---|---|
| LOBBY | 房主 `start`（人齐后） | 座位表、筹码 |
| BETTING | 当前行动座位（`look` 随时可用） | 奖池、注额、每人在局/弃牌/闷或明、本局投入；**没有牌面** |
| SETTLE | 任意玩家 `next` | 赢家、奖池归属、各家筹码变化 |
| OVER | 房主 `restart` | 最终赢家 |

## 4. 协议扩展

| 类型 | 方向 | payload |
|---|---|---|
| `ZJH_LOBBY` | Host → 单人 | `{You, Seats[], Chips, Ante, MaxStake, MaxRounds}` |
| `ZJH_START` | Host → 全员 | `{Round, Ante, Seats}` |
| `ZJH_PUBLIC` | Host → 全员 | 奖池、注额、轮数、各家状态（**无牌面**） |
| `ZJH_HAND` | Host → 单人 | `{You, Cards []Card, Looked bool}`；**没看牌时 Cards 为空** |
| `ZJH_PEEK` | Host → 比牌的两人 | `{A, B, CardsA, CardsB, Loser}`（各收到一份，牌面只给这两人） |
| `ZJH_ACTION` | Client → Host | `{Kind: look\|call\|raise\|fold\|compare, Amount, Target}` |
| `ZJH_EVENT` | Host → 全员 | `{Seat, Text}` |
| `ZJH_NEXT` | Client → Host | 请求下一局 |

**隐私红线**（要有测试断言）：
1. 公共报文里**不出现任何牌面**
2. `ZJH_HAND` 在没看牌时 `Cards` 必须为空
3. `ZJH_PEEK` 只发给比牌的两个人

## 5. 核心接口草图

```go
// internal/zjh/hand.go
type Card = ddz.Card
type Rank = ddz.Rank

type HandKind string // BAOZI / TONGHUASHUN / JINHUA / SHUNZI / DUIZI / SANPAI

type Hand struct {
    Kind HandKind `json:"kind"`
    Key  []Rank   `json:"key"` // 比较用的关键点数，从大到小
}

func Evaluate(cards []Card) Hand   // 识别牌型（非法张数返回空 Hand）
func Compare(a, b Hand) int        // -1 / 0 / +1；花色不参与，0 表示完全一样大

// internal/zjh/game.go
type Game struct {
    Players  []Player // Cards / Looked / Status / Bet
    Chips    []int
    Pot      int
    Stake    int
    Ante     int
    MaxStake int
    MaxRounds int
    Turn     int
    Phase    Phase
    Round    int
    Winner   int
    // ...
}

func NewGame(rng *rand.Rand, seats, chips, ante, maxStake, maxRounds int) *Game
func (g *Game) Apply(seat int, act Action) ([]Event, error) // 唯一入口
func (g *Game) Cost(seat int) int                           // 本回合要付多少（闷牌半价）
func (g *Game) PublicView() PublicView                      // 无牌面
func (g *Game) PrivateView(seat int) PrivateView            // 没看牌时 Cards 为空
func (g *Game) NextRound() []Event
```

**关键约定**：与前三款一致——客户端只发命令、只渲染收到的视图，所有校验都在 `Apply` 里做。

## 8. 验收清单

- [ ] 2~6 人开房；第 7 个连接被拒
- [ ] 开局各付底注入池；奖池 = 底注 × 人数
- [ ] **没看牌之前，自己的报文里查不到自己的牌**（改客户端也看不到）
- [ ] `look` 之后只收到自己的三张牌；别人依然看不到
- [ ] 闷牌跟注只付半价；看牌后付全价；筹码不够只能弃牌
- [ ] 加注必须在 `stake` 与 `maxstake` 之间；到顶后加注被拒
- [ ] 轮数到顶后只能比牌或弃牌，跟注被拒
- [ ] 比牌：输的人弃牌；平局时闷牌方赢；都明/都闷时主动比牌者输
- [ ] 比牌结果全场可见，但**牌面只有比牌双方收到**
- [ ] 只剩一人没弃牌 → 他拿走奖池，结算数字正确
- [ ] 筹码输光出局；只剩一人有钱整桌结束
- [ ] 掉线本局作废回大厅；`next` 开下一局
- [ ] 回归：`go test ./...` 全绿，前三款游戏照旧可用

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 手牌提前泄漏（发牌就下发） | `PrivateView` 在 `Looked == false` 时返回空数组；端到端测试扫描报文里的牌数 |
| 比牌牌面泄漏给全场 | `ZJH_PEEK` 只单播给两人；测试断言第三方收不到 |
| 全闷无限跟注 | `maxrounds` 到顶只能比牌或弃牌 |
| 平局裁决不一致 | 规则写死（闷牌占优 / 比牌者输），并有专门测试 |
| 奖池算错 | 逐项断言"净额 = 奖池 − 自己投入"，并校验筹码守恒（玩家之间流动，不凭空产生） |
| 与前三款共用 protocol/room 造成回归 | 只做增量；回归跑全量测试 |

### 实现时踩到的三个点

- **结算不能退本金**：第一版 `finish()` 先把每人投入退一遍再发奖池，等于凭空造钱；
  测试里"筹码总额 116 ≠ 60"直接把它顶出来。现在只把奖池发给赢家并把奖池清零
- **去重 key 不能带别人的状态**：驱动用的机器人最初把"奖池/注额"也放进去重 key，
  结果别人一跟注它就重新决策、重复发 `look`，被房主拒绝后卡住。改成只看
  "自己的状态 + 回合 + 阶段"就稳了
- **看牌与否要用公开信息判断**：客户端的私密视图比公共状态晚到一拍，
  用私密视图判断"我看了没"会重复发 `look`；`Looked` 本来就是公开字段，用公共座位状态即可
